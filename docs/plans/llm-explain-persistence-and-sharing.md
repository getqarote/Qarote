# LLM Explain — Persistence, Export & Sharing (PR A)

> **PR split.** This is PR A. PR B (Managed quota counter + caps +
> upsell + 80% warning + BYOK fallback) is scoped in
> `docs/plans/llm-managed-quota.md` and depends on the stream
> contract refactor in this PR.

## Problem

Today the "Explain this" feature is volatile:

- The streamed response lives only in React state inside the drawer
  (`ScanRevealExplainDrawer.tsx`, `DiagnosisCard.tsx`,
  `TracingMessageRow.tsx`). Closing the drawer destroys it
  (`reset()` on unmount).
- Reopening the same finding re-runs a full LLM call (cost + latency,
  repeated per operator click).
- The operator cannot copy, export, share, or permalink the diagnosis
  without manual text-selection + Cmd+C — fragile while the cursor is
  animating.
- A post-mortem author cannot link to "the explanation Qarote gave at
  04:12 UTC when the incident fired." Today there is no such object.

## Goal

Turn each LLM explanation into a first-class, addressable, exportable
artefact:

1. **Persist** the full response once the stream completes successfully.
2. **Re-serve** the cached response on subsequent opens (no re-spend
   unless the operator explicitly regenerates).
3. **Export** via Copy markdown (primary) and Copy share link
   (secondary) from the drawer.
4. **Share** via a permalink scoped to workspace membership.

Out of scope (deferred follow-ups):

- Managed LLM quota counter + caps + upsell (moved to PR B,
  `docs/plans/llm-managed-quota.md`).
- PDF export (cheapest path: `window.print()` + print stylesheet).
- Public read-only links (no-auth share).
- Multi-version diffing UI.
- Editable / annotated explanations.
- Rule-edit drift detection (v1 hint covers `promptVersion` only).
- In-app feature announcement (release covered by changelog only).
- Top-ups (tracked as issue
  [getqarote/Qarote-EE#96](https://github.com/getqarote/Qarote-EE/issues/96)).

## Subject types

Three entry points exist today; the persistence layer addresses all
three with one model holding three nullable foreign keys + a CHECK
constraint enforcing exactly one is non-null. Polymorphic
`(subjectType, subjectId)` was rejected: it required a nightly
orphan-cleanup cron and provided no DB-level guarantee against
cross-tenant ID reuse.

| Feature           | Subject model              | UI entry point                  |
|-------------------|----------------------------|---------------------------------|
| `explain_finding` | `IncidentDiagnosisRecord`  | `DiagnosisCard.tsx`             |
| `explain_finding` | `ConfigFinding` (scan)     | `ScanRevealExplainDrawer.tsx`   |
| `explain_trace`   | `MessageTraceEvent` group  | `TracingMessageRow.tsx`         |

The `digest` feature is excluded — daily cron, already has its own
`DigestLog` persistence.

## Schema

New table `LlmExplanation`. All Prisma columns use `@map` to snake_case
so the raw SQL CHECK and partial indexes (which reference snake_case
identifiers) match the actual DB column names.

```prisma
model LlmExplanation {
  id            String   @id @default(uuid())
  workspaceId   String   @map("workspace_id")

  /// Exactly one of these three is non-null, enforced by a CHECK.
  /// Gives cascade delete for free (no orphan cron), and prevents
  /// cross-tenant subjectId collisions at the DB level.
  incidentFindingId String? @map("incident_finding_id")
  configFindingId   String? @map("config_finding_id")
  traceEventId      String? @map("trace_event_id")

  /// Prompt version that produced this content. Lets us invalidate
  /// stale explanations when the prompt builder changes (1.x → 2.0 at
  /// staging→prod cutover).
  promptVersion String @map("prompt_version")

  /// Provider + model that generated it. `model` is part of the
  /// partial unique index so a workspace switching from Ollama
  /// llama3.2 to Anthropic Sonnet does not serve cached Ollama output.
  provider      String
  model         String

  /// Full assistant message, post-stream, post-redaction. Redaction
  /// is re-run on the assembled content before INSERT — chunked
  /// redaction can miss tokens that straddle stream-frame boundaries.
  content       String   @db.Text

  inputTokens   Int @map("input_tokens")
  outputTokens  Int @map("output_tokens")

  /// User who triggered the generation. FK with onDelete: SetNull —
  /// banner copy must handle null ("regenerated 2h ago", author
  /// elided) instead of "regenerated by Paul".
  createdBy     String?  @map("created_by")
  createdAt     DateTime @default(now()) @map("created_at")

  /// Soft-delete on regenerate: archives the old row instead of
  /// overwriting, so a permalink shared in Slack still resolves to a
  /// (banner-flagged) historical version.
  supersededBy  String?   @map("superseded_by")
  supersededAt  DateTime? @map("superseded_at")

  workspace        Workspace                @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  incidentFinding  IncidentDiagnosisRecord? @relation(fields: [incidentFindingId], references: [id], onDelete: Cascade)
  configFinding    ConfigFinding?           @relation(fields: [configFindingId], references: [id], onDelete: Cascade)
  traceEvent       MessageTraceEvent?       @relation(fields: [traceEventId], references: [id], onDelete: Cascade)
  creator          User?                    @relation(fields: [createdBy], references: [id], onDelete: SetNull)

  @@index([workspaceId, createdAt])
  @@index([incidentFindingId])
  @@index([configFindingId])
  @@index([traceEventId])
  @@map("llm_explanations")
}
```

**CHECK constraint** — added via raw SQL in the migration:

```sql
ALTER TABLE llm_explanations
  ADD CONSTRAINT llm_explanations_exactly_one_subject CHECK (
    (incident_finding_id IS NOT NULL)::int +
    (config_finding_id IS NOT NULL)::int +
    (trace_event_id IS NOT NULL)::int = 1
  );
```

**Partial unique indexes** — one per subject type, scoped to live rows
only. The WHERE predicate is referenced again in `ON CONFLICT` for
upserts (see Backend changes).

```sql
CREATE UNIQUE INDEX llm_explanations_live_incident
  ON llm_explanations (incident_finding_id, prompt_version, model)
  WHERE superseded_at IS NULL AND incident_finding_id IS NOT NULL;

CREATE UNIQUE INDEX llm_explanations_live_config
  ON llm_explanations (config_finding_id, prompt_version, model)
  WHERE superseded_at IS NULL AND config_finding_id IS NOT NULL;

CREATE UNIQUE INDEX llm_explanations_live_trace
  ON llm_explanations (trace_event_id, prompt_version, model)
  WHERE superseded_at IS NULL AND trace_event_id IS NOT NULL;
```

**Retention.** 180-day rolling hard delete via a new monthly cron
`apps/api/src/cron/llm-explanation-retention.cron.ts`. Aligns with
GDPR Art. 5(1)(e) storage limitation. Document in DPA before merge.

## Backend changes

### Stream contract refactor (`llm.service.ts`)

`streamExplain` currently yields `string` chunks. Two changes:

1. Yielded type becomes a tagged union:
   ```ts
   type StreamChunk =
     | { type: "text"; text: string }
     | { type: "meta"; explanationId: string; fromCache: boolean }
     // PR B (quota) adds:
     // | { type: "quota"; used: number; cap: number; resetDate: string };
   ```
2. After the text loop completes successfully, yield exactly one
   terminal `meta` chunk. The router serializes `text` chunks as SSE
   `data:` lines and the `meta` chunk as an SSE `event: meta` named
   event followed by `data: {...}`.

The existing digest cron caller is updated to ignore `meta` chunks (it
collects text only). PR B will add `quota` to the union — the parser
must be event-block-based to absorb new event names without changes.

### Read-through cache + persistence (`llm.router.ts`)

1. **Lookup before generating.** Resolve which subject FK applies from
   the request, then SELECT the live row matching
   `(<subjectFK> = :id, prompt_version = current, model = resolved,
   superseded_at IS NULL)`. On hit: yield `meta` with that
   `explanationId` + `fromCache: true`, then yield a single `text`
   chunk with the persisted content, then return. ~0 ms TTFB, $0 cost.

2. **Race-safe write** via partial-index UPSERT using raw SQL —
   Prisma's `upsert` compiles to SELECT → branch → INSERT/UPDATE in
   two round trips and is NOT atomic under concurrent first-write.
   Use `$executeRaw`:
   ```sql
   INSERT INTO llm_explanations (...) VALUES (...)
   ON CONFLICT (<subject_fk>, prompt_version, model)
     WHERE superseded_at IS NULL AND <subject_fk> IS NOT NULL
   DO UPDATE SET id = llm_explanations.id  -- no-op, just returns existing id
   RETURNING id;
   ```
   Two concurrent uncached operators each invoke `streamExplain` (cost
   paid twice — unavoidable without a pre-stream lock); only one row
   persists; the loser receives the winner's `id` back via RETURNING
   and reports it in the `meta` event.

3. **Re-run redaction on the assembled content** before INSERT.
   Streaming redaction is per-chunk and can miss tokens that straddle
   frame boundaries; persistence is durable, so it gets the stricter
   pass.

4. **Separate try/catches** for the explanation persistence vs any
   side-effects (PostHog emit, future quota counter from PR B).
   Counter or analytics failures must NOT prevent explanation
   persistence — cache value > exact bookkeeping. Log each failure
   independently to Sentry.

### Regenerate flow

Add `regenerate?: boolean` to both `ExplainFindingBodySchema` and
`ExplainGenericBodySchema`. Sequence when `true`:

1. **Register `AbortController` in the in-flight registry FIRST**, so
   any subsequent concurrent regenerate aborts this one cleanly.
   Registry: `Map<string, { controller: AbortController; expiresAt:
   number }>` at `apps/api/src/ee/services/llm/inflight.ts`. Key:
   `${workspaceId}:${subjectType}:${subjectId}`.
2. **Short transaction** — `UPDATE llm_explanations SET supersededAt =
   NOW() WHERE <subjectFK> = :id AND supersededAt IS NULL`. Frees the
   partial unique index. Does not hold the tx across the stream.
3. **Stream + INSERT on completion**, same UPSERT path as a fresh
   generation.
4. **Always delete the registry entry** on completion, abort, OR
   error.

**Race window — documented limitation.** Between step 2 (supersede)
and step 4's eventual INSERT, a third request finds no live row and
starts a fresh generation. UPSERT serializes the outcome (one row
persists, both clients see the same id) but two streams pay cost.
Bounded to one stream duration (~30s); not worth additional locking.

**Registry hardening.** Every insert gets a hard TTL of 5 minutes via
`setTimeout` that deletes the entry. Defends against leaked entries
from crashed handlers. Registry size logged once per minute to detect
unbounded growth.

**Per-process limitation — documented.** Registry is in-memory; multi-
dyno deployments lose cross-instance abort coordination. This is a
cost leak, not a correctness bug. Move to Redis if/when the API runs
multi-instance.

### Rate limit on regenerate

Per-user, 10 regenerations/hour. Implemented as Hono middleware on
the `regenerate=true` branch of POST `/explain`. Returns 429 with
`Retry-After`. Backed by an in-memory token bucket (same per-process
limitation as the registry; acceptable for v1).

### CSRF protection on POST `/explain`

`/explain` is a Hono route, not tRPC, so the `x-trpc-source` defence
doesn't cover it. Require **both**:

1. `Origin` header validation: must match
   `process.env.APP_BASE_URL` or be absent (same-origin fetches).
2. Custom header `x-qarote-explain: 1` on every POST. Mirrors the
   tRPC pattern; cross-site form-submit attacks can't add arbitrary
   headers.

Rate limit is the third line of defence, not a CSRF substitute.

### GDPR Art. 17 — synchronous cascade

The Prisma `onDelete: Cascade` on the workspace + three subject FKs
already handles deletion synchronously. The retention cron is a
time-based purge layer, not the deletion mechanism — subject deletion
must remove the explanation in the same transaction, not after a
delay.

### New API endpoint

**`GET /api/llm/explanations/:id`** — JSON for the permalink page.

- Session auth (same as POST `/explain`).
- Membership check against the explanation's `workspaceId`.
- 404 (not 403) on mismatch — no existence oracle.
- Constant-time response on miss vs unauthorized (single
  `setTimeout` floor) — prevents timing enumeration.
- `listForSubject` companion: workspaceId from session AND the subject
  row is re-verified to belong to that workspace via JOIN (not
  SELECT-then-compare) to avoid TOCTOU. A member of workspace A
  passing B's `subjectId` gets an empty list. The tRPC input schema
  MUST NOT contain a `workspaceId` field — the value is derived from
  session context only.

### Hono HTML route for OG unfurling

**`GET /explanations/:id`** — serves HTML with dynamic OG tags for
bot user-agents, and falls through to the SPA for humans.

**Implementation pattern** (avoids the redirect-script flash):

```ts
app.get("/explanations/:id", async (c, next) => {
  const ua = c.req.header("user-agent") ?? "";
  if (!isUnfurlBot(ua)) return next();   // humans → SPA fallback

  const row = await loadOgData(c.req.param("id"));  // ruleKey + severity only
  if (!row) return c.html(genericOgShell(), 200);

  return c.html(ogShellFor(row), 200);
});
```

- `isUnfurlBot` is a small UA allowlist: `Slackbot-LinkExpanding`,
  `Twitterbot`, `facebookexternalhit`, `LinkedInBot`, `Discordbot`,
  `WhatsApp`, `TelegramBot`. Spoofable, but it's an unfurl convenience,
  not a security boundary.
- This route MUST be registered **before** the SPA catch-all
  (`app.get("*", ...)` at `server.ts:147`).
- This route MUST work in both self-hosted AND cloud modes. The
  current static-serving gate at `server.ts:124` is `!isCloudMode()`;
  register the OG route OUTSIDE that gate so the cloud deployment
  (where the SPA is served from a CDN) still has the OG endpoint
  available.

**OG content** is strictly the **humanized rule display name** + the
severity. The rule catalogue already maps `QUEUE_DEPTH_HIGH` →
`"Queue depth high"` for the drawer; the OG route reuses the same
map. Output:

```html
<meta property="og:title" content="Queue depth high · HIGH severity" />
<meta property="og:description" content="View this RabbitMQ diagnosis in Qarote." />
<meta property="og:image" content="https://qarote.io/og-default.png" />
<meta property="og:url" content="https://app.qarote.io/explanations/:id" />
```

No queue name, no vhost, no explanation content. Safe to serve
unauthenticated.

## Frontend changes

### `useStreamingExplain.ts` — SSE event-block parser

The current parser at lines 121–156 is `data:`-only and dispatches
per-line. SSE requires event-block parsing: events are separated by
blank lines, an event can have an `event:` field + multiple `data:`
fields, all of which must be assembled before dispatch.

Refactor (~50 LOC to leave headroom for PR B `quota` event):

1. Buffer until blank line. On blank line:
   - Concatenate `data:` lines into one string.
   - If `event:` line was seen, dispatch on the named-event handler
     (`meta` → parse JSON, set `explanationId`/`fromCache`).
   - Otherwise dispatch to the default text handler.
   - Switch on `eventName` — new event names (`quota` in PR B) add
     one case branch only.
2. Retire the `[DONE]` sentinel. The `meta` event is the new
   terminator. Server stops emitting `[DONE]`.
3. Return shape extended:
   `{ text, isStreaming, error, explanationId, fromCache, stream, reset }`.
   Reset all on `reset()` and on each `stream()` call.
4. Keep the existing request-id staleness guard exactly as-is.

### Supersede banner

When `/explanations/:id` resolves a row with `supersededAt != NULL`:

```
[Banner — sticky, top of content]
This explanation was superseded by a newer one (regenerated 2h ago).
[View latest →]
```

- Server-renders into the page metadata (trust contract is part of
  the document, not a client overlay).
- `role="status"`, `aria-live="polite"` once on mount (not on every
  scroll).
- Author display: "regenerated by <name> · 2h ago" when `createdBy`
  resolves to a live user; "regenerated 2h ago" when `createdBy` is
  null (deleted user, SetNull). Never "by a deleted user".
- **Mobile ceiling**: `max-h-24` on the banner content; collapses to
  a 32-px pill ("Superseded · View latest →") after the user has
  scrolled past it, anchored via `IntersectionObserver`.

### Prompt-version drift hint

When the row's `promptVersion` differs from the current
`FINDING_PROMPT_VERSION`, render a single inline line next to the
Regenerate button:

> Prompt updated since this explanation · [Regenerate]

Otherwise the bar is silent. **v1 scope is `promptVersion` only.**
Rule-edit drift detection is a follow-up — requires `updatedAt`
tracking on rule definitions which does not exist today.

## Migration & rollout

**Single PR (PR A).** Ordered commits within the PR:

1. **Schema migration** — `LlmExplanation` model + raw SQL (CHECK +
   3 partial unique indexes).

   `{type:'text'|'meta'}` tagged union; router serializes `meta` as
   named SSE event. Digest cron updated to skip non-text chunks.

   for PR B `quota` event).
3. **In-flight registry + CSRF + rate limit middleware** at
   `apps/api/src/ee/services/llm/inflight.ts` and Hono middleware.

   (`$executeRaw` with `ON CONFLICT (...) WHERE ... DO UPDATE`

5. **Regenerate flow** — registry register → short-tx supersede →
   stream → INSERT, with always-delete in `finally`.
6. **Retention cron** — monthly purge of rows older than 180 days.
7. **GET endpoints** — `/api/llm/explanations/:id` + `listForSubject`
   tRPC (input schema omits `workspaceId`) + Hono `/explanations/:id`
   HTML route (registered before SPA fallback, available in both
   cloud and self-hosted modes).
8. **`useStreamingExplain` event-block parser + extended return shape.**
9. **`ExplanationActions` shared component** wired into 3 drawers.
10. **`pages/Explanation.tsx`** + React Router wiring + supersede

12. **Stream-error inline card** in drawers.
13. **Markdown sanitiser** on the rendering path.

## Observability hooks

- **PostHog**: emit `llm_explanation_persisted`,
  `llm_explanation_cache_hit`, `llm_explanation_regenerated`,
  `llm_explanation_shared`, `llm_explanation_view_superseded`,
  `llm_explanation_drift_hint_shown`. Lets us measure cache hit-rate,
  share-link adoption, drift hint frequency.
- **Sentry**: wrap the cache-write path in its own try/catch;
  failures reported as warnings, must not break the user-visible
  stream. Sentry transaction around the stream surfaces p95 latency.
- **Audit log**: no entry. Persistence is per-operator-action and
  high-volume; audit log is for governance events.
- **Internal log**: registry size logged once per minute to detect
  leaks.

## Cost & risk

- **Cost saved.** Cache hit-rate target: ≥60% of opens are repeat
  views within 24h. At $0.01–0.03 per explanation (Sonnet pricing,
  current prompt cap), this is meaningful before Managed quota
  even exists.
- **Risk: stale explanation after prompt-version bump.** Drift hint
  surfaces this; operator regenerates one-click.
- **Risk: stale explanation after rule-text edit.** Not detected in
  v1. Acknowledged.
- **Risk: referenced resource deleted.** Not detected in v1. The
  `createdAt` timestamp on the page implicitly signals the snapshot
  is historical.
- **Risk: share-link leakage.** Membership re-check on every GET.
  External recipient can't load the page content. Bots fetching OG
  tags get the humanized rule display name + severity only — no
  contextual data.
- **Risk: PII in persisted content.** Re-redaction on assembled
  content + 180-day retention + sync cascade on subject delete cover
  GDPR Art. 5 and Art. 17. Document in DPA before merge.
- **Risk: CSRF on regenerate.** Origin check + custom header
  `x-qarote-explain` cover the Hono POST. Rate limit is the bounded
  blast-radius defence, not the CSRF defence.
- **Risk: registry leak.** 5-min TTL + always-delete in `finally` +
  size logging.
- **Risk: cluster-aware abort missing.** Single-instance assumption
  documented; cost leak in multi-instance deploys until Redis backed.
